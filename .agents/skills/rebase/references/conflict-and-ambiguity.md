# Conflict and ambiguity

Apply one combined-intent process to replay, saved-work restoration, remote integration, and correction conflicts.

1. Identify the conflicting operation, affected hunks, and each task or commit intent that produced them.
2. Trace affected producers, consumers, interfaces, prompts, documentation, and observable behavior.
3. Enumerate semantic outcome classes. Preserve every intent compatible with the bound goal and current system.
4. Test each supported class with repository-required checks and checks covering every traced interaction.
5. Select an outcome only when exactly one class preserves all compatible intent and its relevant checks pass.
6. Treat side labels, apparent recency, and claims of being newer or better as mechanics, not outcome selectors.
7. When no class works or multiple incompatible classes remain, pause and name the alternatives and evidence.
8. Route any failed or unobservable inspection or check to stopped-state recovery before another mutation.
